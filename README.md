# video-farrowing-prediction

Nest-building detection and time-to-farrowing prediction from two
independent activity-sensing modalities: an ear-tag accelerometer and
video-derived optical-flow activity. Includes symbolic-regression
prediction, cross-signal transfer (training on accelerometer, testing
on video, with three feature-scaling strategies), a styled figure set,
a recording-gap report, and a full detection-triggered ("online")
evaluation pipeline.

A fully synthetic example sow ships under `data/raw/` so the whole
pipeline runs out of the box — see [Data layout](#data-layout).

## Installation

```
pip install -e ".[test]"
```

Requires Python >= 3.10. `pyoperon` (the symbolic-regression engine)
and `Rbeast` (one of three nest-building detectors) both ship real
wheels on PyPI for common platforms, so a plain `pip install` is
usually enough; if either fails to build on your platform, see their
own project pages for alternative install instructions (e.g. conda-forge).

## Data layout

```
data/raw/
  accelerometer/<sow>.csv          # timestamp, Acc            (1-minute resolution)
  video/<sow>_activity.csv         # Timestamp, Flow_totals    (sub-minute resolution)
  meta/<sow>.csv                   # farrowing onset, crate times, pen type, ...
```

- `accelerometer/<sow>.csv`: columns `timestamp, Acc`, already at
  1-minute resolution.
- `video/<sow>_activity.csv`: columns `Timestamp, Flow_totals`, at
  whatever native sub-minute resolution you have — it's resampled to a
  1-minute mean on load, so the exact native rate doesn't matter.
- `meta/<sow>.csv`: one row with (at minimum) `Sow.number.trial.number`,
  `Date.of.sow.introduction.to.farrowing.pen`,
  `Datetime.of.sows.farrowing`, `end.of.farrowing`, `pen.type`,
  `closing.crate`, `opening.crate`. A sow that was never crated uses the
  literal string `"uncrated"` for both crate columns rather than being
  left blank.

A sow is "complete" once all three files exist for the same `<sow>` id.

**Bundled example.** `data/raw/{accelerometer,video,meta}/sample_sow.*`
is fully synthetic data (generated by `scripts/generate_sample_data.py`)
with the same file structure and column names as real data, standing in
for an actual animal purely so every command below runs immediately
after cloning. Regenerate it with `python scripts/generate_sample_data.py`.
Real raw data isn't published in this repo; a preprocessed, anonymized
training dataset derived from the real archive is published separately.

Drop in your own sows under the same three folders (any id works as a
filename, not just `sample_sow`) to run on real data.

## Usage

Every command below runs from the repo root and works immediately
against the bundled `sample_sow` example.

### Detection + prediction case study (one sow)

```
python -m video_activity.case_study --sow "sample_sow"
```

Runs all three nest-building detectors (NestDetect, CUSUM, BEAST) on
both signals and writes `<sow>_detection.png` + `<sow>_summary.json`
to `out/video_case_study/`.

### Batch suite (every sow you have)

```
python -m video_activity.suite
```

Runs the case study for every complete accelerometer+video+meta
triplet found under `data/raw/`, aggregates detection performance
across sows, and writes a report to `out/video_case_study/suite/`.

### Recording-gap report

```
python -m video_activity.gap_report
```

Finds every gap in each sow's recording and reports where it falls
relative to farrowing onset — useful for sanity-checking a sow before
trusting its detection/prediction results.

### Symbolic-regression training + cross-signal transfer

```
python -m video_activity.sr_transfer
```

Trains an Operon symbolic-regression model on accelerometer data
(grouped 5-fold CV across sows), then evaluates it on video data under
three scaling strategies: naive (reusing the accelerometer scaler),
domain-level (a fresh video-only scaler), and per-sow (each sow's own
activity divided by its own early-recording baseline). With only one
sow available, this falls back to a single-sow smoke test so the
mechanism is still exercised end to end — rerun with more sows for a
real cross-sow result. Persists the trained model, scaler and per-sow
baselines to `out/video_case_study/sr_transfer/` for the next two
commands to reuse without retraining.

### Online evaluation

```
python -m video_activity.online_eval
```

The deployment-realistic setting: runs detection first, and only
starts the prediction stage once (and if) a detector actually raises
an alarm — using only data available up to each point, unlike a
farrowing-anchored window that already assumes the farrowing time is
known. Reuses the model `sr_transfer.py` persisted.

### Per-animal predictions

```
python -m video_activity.named_sow_eval --sow "sample_sow"
```

Per-instance (not aggregated) true-vs-predicted values for a chosen
list of sows, both farrowing-anchored and online — the data figures 6
and 7 plot.

### Figures

```
python -m video_activity.figures --sows "sample_sow"
```

Seven styled figures with one consistent color palette:
signal comparison, nest-building detection comparison, accelerometer
cross-validation, cross-signal transfer, feature sensitivity, and
per-animal anchored/online prediction scatter. Figures 3-7 need
`sr_transfer.py` and `named_sow_eval.py`'s output to already exist;
figures 1-2 only need the raw sow data.

## What's in each module

- `video_activity/` — the pipeline: data loading (`ingestion.py`),
  single-sow case study (`case_study.py`), batch runner (`suite.py`),
  per-sow instance-table pooling (`pooling.py`), symbolic-regression
  training + transfer (`sr_transfer.py`), the online evaluation setting
  (`online_eval.py`), per-animal predictions (`named_sow_eval.py`),
  the recording-gap report (`gap_report.py`), and the styled figure
  set (`figures.py`).
- `farrowing_prediction/training/` — `instance_tables.py` (sliding-window
  feature/target extraction, farrowing-anchored and online),
  `cross_signal.py` (per-domain/per-sow scaling, grouped cross-validation,
  transfer evaluation, feature sensitivity), `operon_sr.py` (the Operon
  symbolic-regression wrapper, including a formula-string persistence
  workaround for a pyoperon pickling limitation).
- `feature_engineering/` — the ten-feature extraction function shared by
  every instance table, and the day-length constants it uses.
- `nest_building/` — the three nest-building detectors (CUSUM, BEAST,
  NestDetect) and detection-vs-ground-truth scoring.

## Tests

```
pytest
```

Most tests are synthetic and need no data; a handful are gated on real
sow data being present under `data/raw/` and run against whatever sows
they find there (the bundled `sample_sow` by default).
